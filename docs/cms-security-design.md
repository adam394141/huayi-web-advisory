# 新官網 CMS 與防竄改設計提案

日期：2026-09-13。狀態：使用者已確認沿用既有作品與文章，以 Advisory 為唯一後續官網。資料庫安全設定仍需實際查證。

## 目標與邊界

以 Advisory 新官網為唯一開發目標，維持現有視覺。提供作品與觀點管理，不做團隊 CMS。不修改原網站、/adam、/adam_cpc、ADS、正式 DNS 或 Production。

防範未授權內容修改並提供可驗證的復原方式；不承諾絕對不被入侵。內容版本復原、程式部署回復與帳號控制權復原是三項不同工作。

## 已確認的資料邊界（取代先前副本提案）

已觀察：新官網讀取 Supabase 的 works、blog_posts 與 published-assets，目前與原網站共用。唯讀函式名稱不是資料庫權限保證。

使用者已澄清 ASP 舊站 huayi.tw 與第一版 Next.js 網站 huayi-web.vercel.app 不同。新官網可沿用第一版的作品／文章資料，不再建立內容副本。第一版官網可淘汰，但不能刪除整個專案或影響 /adam、/adam_cpc、ADS。

先查證 works、blog_posts、Storage 與講師／ADS 的關聯，再對精確範圍實作。正式網域與舊站移交另案驗收。不得因「可淘汰第一版官網」推論可以關閉整個部署或放寬共用權限。

## 建議功能與安全設計

- 共用管理入口、獨立作品與觀點表單。作品含分類、拖移排序、草稿、發布、多圖；觀點含標題、作者、摘要、內容與封面。
- 圖片顯示實際尺寸、比例、格式與容量；封面建議 1200×900，內頁建議寬 1600 以上。保留原圖，不預設裁切；低解析度警示，不冒稱可提升解析度。
- Supabase Auth 登入，管理員由可信伺服器端授權，不以訪客提供的 email 或可自行編輯的 metadata 作權限依據。管理寫入要求已驗證的雙重驗證；設計登入、登出、到期與帳號復原流程。
- 每個讀寫 API 獨立檢查身分與授權，明確限定資料表、欄位、操作、請求大小與來源。不得採用任意 table/action 的高權限通用端點。資料庫 RLS 與 Storage 政策同步驗證。
- 登入及寫入限流不能只靠單一程序記憶體；選用可在 Vercel 多實例部署下生效的機制，依實際可用服務與方案確認。
- 圖文使用限定格式並清洗 HTML；上傳檢查檔案實際格式、尺寸、容量，拒絕可執行內容。檔名不可覆寫既有原檔，草稿圖片不預設公開。
- 內容更新保存版本、操作者與時間；採樂觀鎖避免互相覆蓋。復原建立新版本，不能直接消除修改紀錄。稽核紀錄不提供一般管理介面刪除。
- 備份需與一般內容編輯權限分離；保留資料與圖片備份，實際演練還原。Supabase 平台可用備份功能與保存期需依目前方案查證，不先承諾。
- GitHub、Vercel、Supabase、Cloudflare 帳號均需檢查 MFA、成員及權杖權限；變更須另行授權。平台帳號失守不在 CMS 單獨能防禦的範圍。

## 驗收與完成標準

1. 未登入、非管理員、未完成 MFA 的寫入全部拒絕；公開讀取不得取得草稿。
2. 畸形欄位、跨表操作、跨來源寫入及超量請求被拒絕，錯誤回應不洩漏內部細節。
3. HTML／圖片惡意內容測試只在隔離測試資料進行，不對正式站發動攻擊測試。
4. 作品及文章完成新增、編輯、排序、草稿、發布、版本還原測試；原圖可追溯。
5. 隔離環境演練內容遭竄改後復原，另驗證部署回復流程；缺少憑證或權限不得標記通過。
6. ASP 舊站、講師頁與 ADS 零變更證據；第一版 Next.js 官網可讀取更新後的共用作品與文章。Preview 對應 commit、PR 與 QA 報告。不得 merge main 或改正式 DNS。
7. Notion 僅回寫本輪差異、驗證結果、阻礙及證據連結，詳細實作留 Repo；未驗證項目明確列出。
