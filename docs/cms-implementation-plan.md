# 新官網安全後台實作計畫

## 已確認

沿用 Supabase works、blog_posts，不複製內容。新官網為唯一後續官網；ASP 舊站、講師頁、ADS、正式 DNS 不動。先 Preview，不 merge main。

## 實作順序與驗收

1. 修正資料邊界文件；建立独立本機依賴，避免透過 node_modules 連結修改另一個 checkout。
2. 在伺服器資料讀取出口清洗作品／文章 HTML，避免舊內容直接執行腳本；加入惡意 HTML 回歸測試。JSON-LD 安全序列化。
3. 建立 Supabase Auth 管理入口，不保存密碼，API 驗證真實使用者及 MFA；管理員 ID 明確授權。設定缺失時拒絕服務，不能 fallback 到原密碼。
4. 唯讀查證資料欄位、Auth 與政策；無法確認資料庫端權限、稽核與交易能力時不啟用寫入。service role 的存在不是 SQL migration 權限證據。
5. 在測試資料庫實作作品／文章表單、排序、圖片資訊、版本／樂觀鎖／稽核與復原交易，驗證 RLS、限流及草稿圖片保護。正式資料不可當成可丟棄測試資料。
6. lint、build、單元測試、瀏覽器測試與已部署 Preview 檢查；只有真實完成的驗收才標記通過。
7. Repo 保存技術報告；Notion 保存 delta 與證據連結。資料庫連接或權限阻礙明確交接，不宣稱完成後台。
