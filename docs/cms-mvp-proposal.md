# 新官網後台整理提案（待确认後才實作寫入）

## 建議方式

自訂 Next.js 管理介面，沿用 Supabase 資料服務；不是 WordPress 外掛，也不從零開發驗證或編輯器。正式登入優先用 Supabase Auth、管理員授權與伺服器端檢查。不得沿用舊 useAdmin 把密碼保存於 sessionStorage 作 Bearer 的方式。

## 單一入口、兩個管理區

- 作品：分類、拖曳排序、客戶／專案名稱、介紹、封面、長條多圖、草稿／發布。
- 觀點：標題、作者、分類、摘要、圖文編輯器、封面、草稿／發布。
- 團隊不做 CMS；保留 Adam 講師頁，新講師另套版。
- 圖片旁標示建議尺寸、來源實際尺寸與比例，提供預覽；不強制裁切、不拉伸，Supabase 只保存 WebP 網站版。封面建議 1200×900，內頁建議寬 1600 以上、高度不限。

## 資料與安全 gate

目前新官網與原新版共用作品／文章；不能在沒有決策下修改共用資料。建議先做不寫入正式資料的後台 UI 預覽；確認後決定是否沿用共用資料或另外隔離。不可把 mock 儲存當真實發布。

在實作前確認：新官網是否沿用既有資料作為唯一管理來源，或需獨立資料副本？後者須明確授權複製。原新版未停用前保持零寫入；講師頁／ADS 持續保護。

驗收需覆蓋：未登入／非管理員拒絕、草稿不可公開、輸入驗證、發布欄位一致性、排序保存、圖片原檔保留與預覽、還原策略。密碼與 service role 不得進前端或文件。

## 本輪已查證的問題

- 舊後台 useAdmin 直接保存密碼到 sessionStorage 並用作 Bearer，需替換，不能直接搬用。
- 舊文章後台使用 is_published，新官網讀 status=published，需確認一致性。
- FITI 封面實際只有 120×96 px；圖片放大後仍會模糊，需要尋回高解析原圖，不能宣稱排版修正會提升解析度。
