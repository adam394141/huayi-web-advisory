# CMS 媒體庫設計

日期：2026-09-16  
狀態：依已核准的 Odin CMS 借鑑結論進入第二階段  
範圍：Advisory 新官網後台 `/admin`；不包含第一網站、`/adam`、`/adam_cpc`、ADS、正式 DNS 或 `main` 合併

## 目標

讓 Adam 能集中查看由華翼新後台上傳的網站圖片，辨識圖片屬於哪一筆作品或觀點、是否仍被封面或內文引用，並複製網站圖片網址；不建立第二份檔案、不開放高風險刪除。

## 方案選擇

採用 Supabase Storage 安全索引方案：由受限 SQL 函式讀取既有 `published-assets/cms/{owner}/.../optimized/` 網站版圖片，再由既有管理員 API 提供給後台。這比建立新的媒體資料表更適合目前階段，因為既有圖片可立即納入，也不會因為上傳與資料表寫入其中一步失敗而產生兩套真相。

未採用方案：

- 新建媒體資料表：欄位較完整，但舊圖片需回填，且要維護 Storage 與資料表一致性。
- 在瀏覽器遞迴掃描 Storage：需要多次網路請求，效能與權限控制較差。
- 導入 Sanity／WordPress 媒體庫：會造成 Supabase 與外部 CMS 重複管理，不符合輕量後台方向。

## 第一版功能

- 後台新增「媒體庫」入口，與作品、觀點並列。
- 只列出本人 CMS 路徑的 optimized 網站版，不顯示原圖，不碰 `works/*` 舊資產。
- 支援檔名／內容標題搜尋、作品／觀點篩選、使用狀態篩選、最近上傳排序及分頁。
- 每張顯示縮圖、實際網站像素、網站版檔案大小、所屬內容、封面／內文使用狀態與上傳時間。
- 支援複製圖片網址及開啟原尺寸網站版。
- 圖片以 `contain` 顯示，不裁切。

## 刪除策略

第一版不提供刪除按鈕。系統只判斷「封面使用中」、「內文使用中」、「未找到引用」。未找到引用不等於安全可刪，因為圖片可能仍被尚未索引的內容或外部頁面使用。真正刪除需另做二次掃描、原圖與網站版成對刪除、操作確認及稽核紀錄。

## 資料與權限

- SQL 函式採 `security definer`，固定 `search_path`，只允許 authenticated 呼叫。
- 函式內再次限制指定管理員 UUID、`auth.uid()` 及 `aal2`；不能用前端參數指定其他 owner。
- API 仍先通過 `verifyAdmin`，並限制搜尋長度、集合、使用狀態、頁碼與每頁筆數。
- 回傳公開網站版 URL，不回傳原圖 URL、Storage token、JWT 或任何金鑰。
- GET 回應使用 `private, no-store`。

## 錯誤處理

- SQL 尚未安裝時，媒體庫顯示「媒體索引尚未啟用」，不影響作品、觀點、上傳及發布。
- 圖片讀取失敗顯示佔位，不阻擋其他項目。
- 複製失敗時顯示可理解訊息，不修改任何資料。

## 驗收

- 只有完成 MFA 的獲授權管理員可讀取媒體庫。
- 搜尋、篩選、分頁與總筆數一致。
- 每張只出現一次 optimized 網站版，原圖不公開於媒體庫。
- 顯示尺寸、檔案大小、使用狀態及所屬內容。
- 無刪除能力，既有上傳與內容編輯流程無回歸。
- 測試、lint、TypeScript 與 production build 通過。
