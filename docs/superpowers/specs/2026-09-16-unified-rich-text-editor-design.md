# 華翼 CMS 單一圖文編輯器規格

## 架構決策

保留 Next.js、Supabase、Gemini、管理員驗證、圖片最佳化、版本紀錄與人工發布流程；只淘汰自行開發的多卡片區塊編輯器，改用成熟的 Tiptap 編輯核心。

參考 Sanity Portable Text 與 WordPress Block Editor 的共同原則：底層內容可以結構化，但使用者只看到一個連續文章畫布、情境工具列與文章內圖片。

## 使用流程

1. 編輯封面與文章基本資料。
2. 執行 AI SEO／AEO／GEO 優化並套用為草稿。
3. 優化後正文立即進入單一圖文編輯器。
4. 使用者在文章中放置游標，從編輯器工具列插入圖片。
5. 圖片直接出現在游標位置；點擊圖片可修改替代文字、圖說、更換或刪除。
6. 人工檢查後儲存、預覽與發布。

## 編輯功能

- 單一連續文章畫布，不顯示「文字區塊 1、2、3」。
- H2、H3、H4、段落、粗體、斜體、項目清單、編號清單、引用、連結、表格、復原與重做。
- 文章頁 H1 只來自標題欄位，內文禁止新增 H1。
- 圖片是文章節點，可拖曳位置；維持原比例、不預設裁切。
- 圖片保留 src、alt、caption、網站尺寸、原始尺寸與壓縮資訊。
- 圖片上傳介面屬於編輯器工具列，不再顯示獨立的「新增內文圖片」區域。

## 資料與相容性

- 繼續使用既有 `content` HTML 欄位，不新增資料表、不搬移文章。
- 既有 `figure > img + figcaption` 內容可直接載入與再次儲存。
- AI、版本還原或重新載入帶來的外部正文更新，必須同步進編輯器且不得觸發循環儲存。
- 儲存仍經伺服器 HTML 白名單清洗；圖片只接受既有可信 Supabase Storage 來源。

## Next.js 與效能

- 編輯器只存在管理後台 Client Component，使用 `immediatelyRender: false` 避免 SSR hydration mismatch。
- 不改前台文章渲染方式，不把編輯器套件送到公開網站頁面。
- 圖片二進位檔不寫入文章 HTML；仍由伺服器上傳至 Supabase Storage 後只保存 URL 與中繼資料。

## 不在範圍

- 不導入完整 Sanity Studio 或 WordPress。
- 不建立多人即時協作、留言、媒體庫搜尋或複雜版面設計器。
- 不修改第一網站、`/adam`、`/adam_cpc` 或 ADS。
- 不合併 main、不切換正式網域。

## 驗收條件

- AI 套用後，正文立即出現在單一文章畫布。
- 游標位於任一段落時可插入圖片，圖片不再固定出現在第一段後方。
- 點擊圖片可編輯 alt、圖說、替換及刪除。
- 既有文章、既有圖片與圖說可無損載入。
- 鍵盤輸入不跳動，Safari 與 Chromium 可操作。
- 測試、lint、TypeScript、正式建置與 Preview QA 通過。
